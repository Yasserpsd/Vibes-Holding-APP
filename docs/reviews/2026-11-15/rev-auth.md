## Problems not fixed

**Android emulator item 23 — settled.** The cause described below was confirmed on the emulator by the Android-run session and fixed in `FormField.tsx` (`glowFrame`); round 6 removes the last two box shadows that my files put on an input. The note is kept as the record.

**The typed e-mail sat about 10 px from the border on sign-in: the cause was not in the identifier.** Both modes of `LoginIdentifier` use the same `FormField` with the same style, so there is nothing to equalise there. The cause, read in this project's React Native source: on focus `FormField.tsx:72` adds `styles.inputFocused` (`FormField.tsx:115`), which carries `boxShadow: shadows.glowGoldFaint`. On Android every change of that prop runs `BackgroundStyleApplicator.setBoxShadow`, which ends with `view.background = ensureCompositeBackgroundDrawable(view).withNewShadows(…)` (`BackgroundStyleApplicator.kt:418-420`): a new `LayerDrawable` that still holds the EditText's own themed background as a layer (`CompositeBackgroundDrawable.kt:75-79`, whose comment names exactly this: «an EditText style may set padding on a TextInput»). Android's `View.setBackground` then takes the drawable's padding, so the field falls back to the theme's 4 dp side padding: 4 dp × 2.625 = 10.5 px, against 16 dp + border ≈ 46 px. That matches the measurement, and it explains why only the focused field shows it and why the sign-up form does not (inside a `FormCard` the focus changes the border only, no shadow). It therefore affects every dark-palette `FormField` while focused, not only this one; a centred code field hides it. A constant `boxShadow` passed from the identifier would not help: React re-sends the key whenever an earlier style in the array changes it, and the native setter swaps the background again. Proposal for the owner of `FormField.tsx` (the Android-run session, which can confirm on the emulator in a minute): keep the glow off the TextInput on Android — either `inputFocused` / `paperInputFocused` without `boxShadow` when `Platform.OS === 'android'`, or, to keep the look, move the glow to a wrapping `View` around the input (a plain View has no themed padding to fall back to). The same applies to `codeFocused` in `app/auth/verify.tsx` and `app/auth/totp.tsx` (mine; left alone because the text is centred and nothing shows). Not verified on a device.
